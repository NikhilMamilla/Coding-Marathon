Question 4 · requirements brief

What this system does

An industrial facility runs several production machines that stream status, temperature, vibration, and production-count events. This pipeline reads that machine roster and event log, rejects anything incomplete, duplicated, out of order, or tied to an unknown machine, flags operating anomalies against each machine's own limits, and rolls the rest into per-machine statistics. The flow is end to end: CSV files in, CSV reports and a console summary out.

01

Validate

Every field checked against a fixed priority order, so one record gets exactly one reason code even when several rules fail.

02

De-duplicate

Machine IDs and Event IDs are frequency-counted across the whole file first, so every occurrence of a duplicate is rejected, not just the second one.

03

Order & detect

Events must not run backward in time per machine; accepted events are then checked for temperature and vibration limit breaches.

04

Report

Machine-wise statistics, an anomaly log, and a rejection log, each with a fixed header, row order, and decimal format.
